verifies that every contents entry points to the page that really holds the heading.

## Workflow diagram accuracy

All 45 diagrams were reviewed node by node against the implementation (`tasks.ts`, `cases.ts`, `saas.ts`, `scheduling.ts`, the
offline queue, stores and security rules); 37 were corrected (for example: the subscription lifecycle — cancelled and expired
are not final; shared allocations may overlap but exclusive ones may not; complaints and escalations are handled in the admin
app only; My Day ordering; QR scan vs QR evidence; sync triggers). Each diagram's `%% sources:` header names the files it was
verified against, and the check fails if one disappears. Infrastructure-dependent steps are labelled "(pending activation)".

Two points for the product owner:

- **Attendance correction** (wf-38): the data-layer function and rules exist but no screen calls it; the diagram labels it
  "data layer and rules only; no screen yet".
- **Extend trial from past_due** (wf-05): allowed by the code for any past_due subscription but only changes status for
  trial-based ones.

## Classification and security

- `public` articles only are built into the website, search index, sitemap and public PDFs. `authenticated` (platform
  console) and `internal` (operator runbooks) articles are excluded from the build entirely; the build aborts if one leaks and
  the browser test checks pages, links, titles, body text, search entries and PDFs. A public article may not link to a
  restricted one (`help:check`).
- The repository is public, so restricted articles contain procedures only. A scan found no passwords, keys, real e-mail
  addresses or tenant data in `docs/help`. Screenshots come from the local emulators with demo data only; the earlier `live-*`
  evidence images were excluded.
- No article advises weakening security rules.

## Version traceability

newest _What's new_ entry. Every page footer and PDF cover shows the version, publication date and build commit;
`build-info.json` and `pdf/manifest.json` record counts and the commit.

## Known limitations

- Translations: Malayalam, Hindi and Arabic interface strings and 12 article translations are **drafts** — not reviewed by
  native speakers — and are labelled as such. All other articles fall back to English with a notice. Module names are only
  partly translated.
- The public Help Center cannot hold the platform and operator documentation; those exist only as restricted PDFs generated
  locally (`npm run help:pdf`) and must be distributed internally.
- Some infrastructure is still pending activation and is documented as such: the automatic scheduler (needs the scheduler
  account secrets), photo upload (cloud storage), push/e-mail notifications, payments, MFA for the platform console.
- Mobile documentation is based on the Chromium runtime test and the Android build; no physical-device or iOS run.
- Writers noted a few UI details they could not observe directly (e.g. the exact read-only error text staff see, whether
  re-picking a template moves a schedule to the newest version); these are worded conservatively.
- Import row limits: the Import Center enforces 2,000 rows per import while `importLimits.maxRows` in shared code is 5,000; the
  documentation states 2,000 (what users experience).
- PDFs are generated in CI on every Pages build (not committed); the complete manual is ~30 MB because of screenshots.
