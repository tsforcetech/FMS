# Phase 4 schema

All documents live under `companies/{companyId}`, carry `companyId` and `schemaVersion: 1`, and are readable and writable only by active owner/admin members of an active company unless stated. Nothing is deleted. Engines and tables are authoritative in `packages/shared/src/schedule.ts` and `packages/shared/src/cases.ts`; the case transition rules are generated from those tables.

## Occurrence identity

`occurrenceKey = {scheduleId}_r{ruleVersion}_{intended local date}{local time}`. The intended (rule) date is used even when a holiday moves the occurrence, so retries, overlapping runs, and the browser and server runners always target the same document. A run reads the document inside a transaction and only creates it if it does not exist.

## Indexes

30 new composite indexes (177 of 200): tasks by scheduleId/origin/assetId + dueAt; schedules by purpose/status + name; cases by status/site/source + createdAt and status + resolutionDueAt; work orders by asset; escalations by target department; caseEvents by kind + caseId + revision; notifications by recipient + createdAt/readAt; stock movements by work order; task exceptions by site.
