# Phase 5 schema — staff identity and scoped access

All documents live under `companies/{companyId}`. No new database or collection outside the company tree.

| Collection                       | Fields                                                                                                                                    | Who writes                                                                                                                                                                         |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `staffLinks/{uid}`               | companyId, schemaVersion, uid, employeeId, siteIds (≤10), allSites, status (`active`/`revoked`), note, created/updated metadata, revision | Owners/admins only (Administration → Staff access). The person can read their own link. `employeeId` is immutable; access is changed by updating `siteIds`/`allSites` or revoking. |
| `employeeLinks/{employeeId}`     | companyId, employeeId, uid                                                                                                                | Owners/admins, written in the same transaction as the link. Guarantees one login per employee; it can move to another login only after the old link is revoked.                    |
| `members/{uid}` (existing)       | role is one of the existing roles: `site_manager`, `department_manager`, `supervisor`, `technician`, `staff`, `viewer` for staff          | Trusted provisioning only (`scripts/provision-staff.mjs`); owner/admin roles are refused by the script.                                                                            |
| `employees.linkedUid` (existing) | informational copy of the login, used to route notifications                                                                              | Kept in step by the Staff access page; the rules never trust it.                                                                                                                   |
| `workOrders` (extended)          | new action `note` (“Add update” / “Request assistance”) keeps the status and records the text in `caseEvents`                             | Assigned staff, supervisors, admins                                                                                                                                                |
| `notifications` (extended)       | types `task_approved`, `issue_updated`                                                                                                    | Admins and linked staff (limited types)                                                                                                                                            |

## Identity resolution

A request is treated as staff only when **all** of these hold: the caller's `members/{uid}` is active and not a customer, `staffLinks/{uid}` is active, the linked employee is `active` or `probation`, and the company is active. The employee ID always comes from the link, never from the client.

## Access matrix (enforced by `firebase/firestore.rules`)

| Data                                                                                                     | Technician / staff                                                                                                                                                                                           | Supervisor, department or site manager                                                                                 | Owner / admin          |
| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| Tasks                                                                                                    | Read tasks assigned to their employee; start, pause, resume, save progress, submit, restart rework only while the task's site is in scope                                                                    | Read and act on tasks in scope sites: assign, reschedule, approve, request rework, reject (never their own submission) | Everything (Phase 3/4) |
| Task events, submissions, decisions                                                                      | Read for visible tasks; append through the actions above; never edit                                                                                                                                         | Same, plus decisions                                                                                                   | Everything             |
| Task exceptions                                                                                          | Create on their tasks; read the ones they reported                                                                                                                                                           | Read and acknowledge/close in scope                                                                                    | Everything             |
| Work orders                                                                                              | Read assigned or self-reported; create from a task issue or a standalone report in scope; start, hold, resume, add update, resolve when assigned                                                             | All actions in scope sites; raise escalations                                                                          | Everything             |
| Notifications                                                                                            | Own only; create limited types for reviewers                                                                                                                                                                 | Same                                                                                                                   | Everything             |
| Reference data                                                                                           | Own employee record; sites in scope and their locations, facilities and assets; departments, designations, teams, shifts, holidays, task categories, SLA policies; own shift/site/team assignments and leave | Also employees whose primary site is in scope                                                                          | Everything             |
| Members                                                                                                  | Only a role-filtered list of reviewers (uid and role)                                                                                                                                                        | Same                                                                                                                   | Read                   |
| Templates, schedules, scheduler runs, clients, contracts, suppliers, inventory, stock ledger, audit logs | No access                                                                                                                                                                                                    | No access                                                                                                              | Unchanged              |

## Indexes

5 new composite indexes (185 of 200): tasks by assignee + due (descending), status + assignee + due (descending); work orders by assignee + created and by creator + created; task exceptions by reporter + detected.
