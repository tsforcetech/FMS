# Firestore schema v1

## Implemented Phase 0 collections

Document IDs are path keys. `companyId` is a 1–128 character identifier using letters, digits, underscore or hyphen; UID is Firebase Auth's UID. Metadata (M) is required: `schemaVersion: 1`, `createdAt`, `updatedAt` (Firestore Timestamp), `createdBy`, `updatedBy` (actor identifiers). Never store operational timestamps as arbitrary strings.

| Path                                        | Required data                                                                     | Owner / query / archive policy                                                                                                                                           |
| ------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `users/{uid}`                               | M, uid, displayName (1–100)                                                       | Own UID get; only displayName + update metadata may change. No role fields. Trusted creation; identity deletion follows retention review.                                |
| `users/{uid}/companyAccess/{companyId}`     | companyId                                                                         | Trusted routing hint. Own UID list, `orderBy('__name__')`, 25/page with cursor. Client cannot write. Remove hint after membership revocation; stale hints grant nothing. |
| `companies/{companyId}`                     | M, companyId, name (1–120), status active/suspended/archived, valid IANA timeZone | Matching active owner/admin get only. No client write or list. Archive via trusted procedure.                                                                            |
| `companies/{companyId}/members/{uid}`       | M, companyId, uid, role, status active/inactive                                   | Own membership get, or active company owner/admin get. Trusted writes only. Deactivate for revocation; retain historical UID.                                            |
| `companies/{companyId}/auditLogs/{eventId}` | M, companyId, actorUid, action, subjectPath                                       | Trusted append only. Owner/admin direct get. No client create/update/delete/list. Retention controlled by operator.                                                      |

Membership roles: owner, admin, site_manager, department_manager, supervisor, technician, staff, viewer, customer. Only owner/admin can use this Admin foundation. Platform super admin is an external operator concept, not a browser-grantable role. Granular/custom role enforcement and site grants are deferred; their documents remain denied.

`firestore.indexes.json` has no composite indexes because all implemented queries use exact document paths or default document-ID indexing. This is intentional. Emulator tests do not prove future production composite-index availability.

## Future collection specification (architecture, not deployed access)

Every following tenant record is under `companies/{companyId}` with M, companyId and a document ID. Default IDs are Firestore-generated opaque IDs; business labels/tags are separate fields. Reference IDs must resolve **inside the same company**. All client access is denied in Phase 0. Required fields below are proposed v1 minimums. Validate field lengths, enums, timestamp ordering, numeric bounds and reference ownership before enabling each writer. Optional relationships are marked `?`.

Future indexes are query plans, not empty deployed collections. For example `tasks(siteId,status,dueAt)`, `taskEvents(taskId,occurredAt)`, `notifications(recipientUid,readAt,createdAt)`, and `taskSchedules(active,nextRunAt)` will be added and tested with their modules. Array fan-out is avoided. Child document limits and per-query page limits must be enforced in each module.

## Location, stock and task invariants

Location parent must exist in the same site/company, must not be the record itself and cannot create a cycle. Asset location is mandatory; transfers retain previous/current location and actor. A material quantity is not an asset instance. Inventory valuation and purchasing are deferred; never infer monetary values from quantity alone.

Task assignments, template versions, submitted answers and status transitions are separate records. Mandatory evidence is validated by trusted backend/rules when that module is enabled. Record original inspection → fault/escalation → corrective work order → final approval links. A task due date is a UTC Timestamp; schedule wall-clock rules use the site's timezone. Overdue is derived without losing lifecycle state.

## Schema change policy

Version all records; reject malformed Phase 0 documents in the typed data layer. Trusted provisioning validates identifiers, enabled password account and timezone. Migrations must be dry-run first, checkpointed and idempotent, with before/after counts and tested rollback. Archive linked masters and retain immutable events; company deletion is not offered in this release.
