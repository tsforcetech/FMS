# Phase 7 schema additions

All under `companies/{companyId}/`. Rules: `firebase/firestore.rules` (section "Phase 7"). Tests: `firebase/tests/phase7.test.ts`.

## tasks (changed)

| Field         | Type              | Notes                                                                                                  |
| ------------- | ----------------- | ------------------------------------------------------------------------------------------------------ |
| `startedAt`   | timestamp \| null | Server time of the first `start` (reset on `restart`). Rules require `request.time`; never client-set. |
| `submittedAt` | timestamp \| null | Server time of the latest submission. Used for "recorded minutes".                                     |

Older tasks have neither field; reports show duration coverage instead of guessing.

## customerLinks/{uid}

Links a customer-role login to exactly one client. Admin-written; the customer may `get` only their own document.

| Field                                      | Type                  | Notes                                                                                                                              |
| ------------------------------------------ | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `clientId`                                 | string                | Immutable after creation                                                                                                           |
| `clientName`                               | string                | Display snapshot                                                                                                                   |
| `contactName`                              | string ≤120           |                                                                                                                                    |
| `allocationIds`                            | string[] ≤10          | Empty = all allocations of the client; otherwise the login is restricted to these                                                  |
| `places`                                   | list ≤40              | Admin-curated snapshot: `allocationId, contractId, siteId, locationId, siteName, locationName, allocationType, startDate, endDate` |
| `status`                                   | `active` \| `revoked` | Revoked immediately blocks every customer read/write                                                                               |
| `revision`, `createdAt/By`, `updatedAt/By` |                       |                                                                                                                                    |

The member document (`members/{uid}`) must have role `customer`; that is provisioned server-side (`scripts/provision-staff.mjs --role customer`). Staff/admin logins cannot be linked and the script refuses to convert between staff and customer logins.

## serviceRequests/{requestId}

Customer-safe view of a request. ID is generated by the client once per form, so retries are idempotent.

| Field                                                    | Notes                                                                                      |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `clientId, contractId, allocationId, siteId, locationId` | Checked on create against the real allocation (client, active dates, site/location, scope) |
| `reference`                                              | `SR-YYMMDD-XXXXXX`                                                                         |
| `category, priority, description`                        |                                                                                            |
| `status`                                                 | `submitted, in_progress, resolved, closed, reopen_requested, cancelled`                    |
| `complaintId, workOrderId`                               | Set by the team (intake / work order creation)                                             |
| `timeline`                                               | ≤40 `{label, at}` — fixed customer-safe labels only                                        |
| `remarks`                                                | ≤30 `{by: customer\|team, text ≤500, at}` — append-only                                    |
| `resolutionSummary`                                      | Copied from the complaint resolution note                                                  |
| `confirmedAt`                                            | Customer confirmation (once, after resolution)                                             |

Customers may only append a remark, ask to reopen a resolved request (with a remark) or confirm. Admin intake creates a complaint with `sourceType: 'service_request'`, `sourceId: requestId` (deterministic ID `cmp_service_request_<id>`); complaint transitions update the request in the same transaction. Staff cannot read requests; the admin Service Requests page reconciles status for complaints moved on by staff.

Indexes: `(clientId, createdAt desc)`, `(allocationId, createdAt desc)`, `(status, createdAt desc)`.

## maintenanceCosts/{id}

Admin-only, create-only (corrections are new entries). `workOrderId, assetId, siteId, type (labor|vendor|material|other), amount ≥0, currency (ISO 4217), description, incurredDate, recordedBy, recordedAt`.

## complianceRecords/{id}

Admin-only. `category, title, siteId, assetId, facilityId, issuer, reference, issuedDate, expiryDate, evidenceRef, verified, verifiedBy, verifiedAt, notes, status (active|archived)`. `verified` requires `verifiedBy` and `verifiedAt`; the client additionally requires an evidence reference. Status shown: valid / expiring (≤30 days) / expired / evidence pending.

## settings/retention

Admin-only policy record: `gpsDays, attendanceDays, photoDays, notificationDays, auditDays (≥365 in the client), note`. It does not delete anything (see `docs/backup-recovery.md`).

## Unchanged

`members` remain server-written. Customers read nothing else: not sites, locations, clients, contracts, allocations, complaints, work orders, employees or costs. Index total: 190/200.
