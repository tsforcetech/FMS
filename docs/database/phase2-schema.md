# Phase 2 schema

The field definitions are authoritative in `packages/shared/src/operations.ts`; Firestore validators are generated from them. Every document lives under `companies/{companyId}` and carries the Phase 1 metadata (`companyId`, `schemaVersion: 1`, `code`, `name`, `notes`, `status`, timestamps, actors, `revision`, `refCount`, `witnessKind`, `witnessId`). Optional values are stored as `''`.

Subcollections and ledgers:

- `assets/{id}/history/{revision}` — condition, status, site, location, custodian, quantity, transferId; append-only. Transfers are recorded by their transfer record instead of a history row.
- `assetTransfers/{id}` — assetId, from/to site and location, quantity, transferDate, reason, conditionBefore/After, receivedById, actorUid; create-only.
- `stockMovements/{id}` — movementType, materialId, fromStoreId, toStoreId, integer quantity (minor units), movementDate, reason, reference, issuedTo*, reversesId, from/toBalanceAfter; create-only. Reversal ID is `REV-{originalId}`.
- `stockBalances/{storeId}_{materialId}` — storeId, materialId, integer quantity ≥ 0, revision, lastMovementId; written only with its movement.

Units of measure and their fixed decimal places are defined in `packages/shared/src/inventory.ts` (for example kg and litre use 3 decimals, metre 2, each 0). A material's unit cannot change after creation so stored quantities stay exact.

Indexes: every list, filter and selector query is covered by generated composite indexes in `firebase/firestore.indexes.json` (119 total).
