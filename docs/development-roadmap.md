# Development roadmap

Each phase requires implementation, tests and review before the next phase. Do not begin Phase 1 without approval. Existing reference UI is visual guidance; planned domain structure governs all new forms.

| Phase | Scope                                                                                                                                                                                           | Release gate                                                                                                                                                                    |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0     | Source audit, npm monorepo, SDK configuration, Auth, tenant resolution, owner bootstrap, admin shell, rules, tests and CI                                                                       | Verified emulator foundation plus selected-project configuration and live verification documented                                                                               |
| 1     | Companies, clients, contracts, sites, flexible locations, facility types and facilities, working hours                                                                                          | Tenant/site isolation, validated forms, archive/reference integrity, accessible mobile layout                                                                                   |
| 2     | Departments, designations, roles/permissions, employees, teams, shifts, leave/holidays; assets/furniture, suppliers, materials/stores/stock                                                     | Trusted permission workflows, site restrictions, stock invariants and audit trails                                                                                              |
| 3     | Versioned templates, checklist types, RACI, task assignments/execution, submissions, approvals/rework                                                                                           | Historical snapshots, state-transition authorization and evidence validation                                                                                                    |
| 4     | Approved Blaze enablement, scheduler, recurrence and assignment, maintenance/work orders, complaints/escalations, files and notifications                                                       | Idempotency, missed-run recovery, timezones/DST, SLA, retry and security tests                                                                                                  |
| 5     | Staff web: My Day, clear actions, checklists, issues, history and localization                                                                                                                  | Real staff usability tests; no fake background execution                                                                                                                        |
| 6     | Android/iOS, QR/camera/GPS, offline queue and synchronization                                                                                                                                   | Device permissions, replay/conflict resolution, secure local storage, Android/iOS device tests                                                                                  |
| 7     | Reports, dashboards, customer portal, compliance, maintenance costs, audit views, operational monitoring, retention policy and backup status                                                    | Accurate aggregates, scoped customer access, retention/backups, performance and recovery tests                                                                                  |
| 8     | Excel/PDF export, bulk import, company onboarding and starter packs, SaaS plans/subscriptions/entitlements, Sharaco platform console                                                            | Exports match report definitions without silent truncation; validated, idempotent imports; quotas enforced at the write boundary; platform authority separate from tenant roles |
| 9     | Help Center & documentation — help website, user manuals, PDF guides, workflow diagrams, role-wise guides, training material, troubleshooting, searchable knowledge base                        | Content reviewed per role; help identifiers (`setup.*`, `data-help`) resolve to articles                                                                                        |
| 10    | **Planned:** Interactive tutorials & tours — in-app guided tours, new-user walkthroughs, contextual tooltips, role-based training, practice flows, tutorial videos, first-time setup assistance | Tours attach to the Phase 8 onboarding step metadata; can be dismissed and resumed; no effect on live data                                                                      |

## Current status

Phase 0, Phase 1 and the site/contract correction are merged. Phase 2 (people, assets, inventory) and the admin redesign are implemented and tested; see [phase2-report.md](phase2-report.md). Phase 2 Firestore rules and indexes are deployed to the live project (all indexes READY).

Phase 3 (task templates, checklists, versioning, RACI, manual tasks, execution, approvals, rework and history) is implemented and tested on `feature/phase3-tasks-raci-approvals`; see [phase3-report.md](phase3-report.md). Its rules and indexes are deployed and it is merged to `main`.

Phase 4 (recurring schedules, scheduler, assignment, calendar and workload views, preventive maintenance, work orders, complaints, escalations, SLA and in-app notifications) is implemented and tested on `feature/phase4-scheduling-maintenance` without Blaze; see [phase4-report.md](phase4-report.md). Its rules and indexes are deployed and it is merged to `main`. Automatic scheduling, email/push and file uploads are pending activation. Phase 5 (staff web portal, staff identity linking and scoped permissions) is implemented and tested on `feature/phase5-staff-web`; see [phase5-report.md](phase5-report.md). Phase 6 (Android/iOS app with Capacitor: offline-first task execution, QR, photo capture, GPS, attendance, encrypted device storage and conflict-aware sync) is implemented on `feature/phase6-mobile-apps`; see [phase6-report.md](phase6-report.md). Photo upload and push are pending activation (Blaze/FCM); device and iOS builds need hardware/signing. Phase 7 (reports & analytics, management dashboard, customer portal at `/customer/`, compliance records, maintenance costs, audit history, operational monitoring, retention policy and backup status) is implemented and tested on `feature/phase7-reports-customer-portal`; see [phase7-report.md](phase7-report.md). Phase 6 and Phase 7 rules and indexes are deployed and both are merged to `main` and published (15 November 2026). Phase 8 (Excel/PDF exports, Import Center, company onboarding with industry starter packs, SaaS plans, subscriptions and entitlements, invitations and the Sharaco platform console at `/platform/`) is implemented and tested on `feature/phase8-saas-import-export`; see [phase8-report.md](phase8-report.md). Its rules are deployed and it is merged to `main` and published (15 November 2026). Phase 9 (Help Center at `/help/`, 164 articles, 8 role guides, PDF manuals, 45 workflow diagrams, contextual help from every app, documentation CI checks) is implemented on `feature/phase9-help-documentation`; see [phase9-report.md](phase9-report.md). It awaits release authorisation. Phase 10 (interactive tutorials & tours) is planned and not started.

## Phase 0 status

Implemented in source: strict workspace setup, email/password login/reset, Auth persistence, profile read, paginated company discovery, canonical membership checks, selected-company subscriptions, access-denied/error/loading/empty states, responsive foundation shell, secure provisioning, emulator fixtures, schema contracts, closed future collection rules and CI.

Deferred: operational CRUD screens, production onboarding UX/invitations, custom roles/site grants, file uploads, scheduling, notifications, mobile, reporting and customer portal.

Unverified/manual: selected real Firebase project, real rules deployment, real owner provisioning, live email/reset delivery and Hosting deployment. See `phase0-report.md` for exact test evidence and repository delivery status.

Phase 1 starts with requirements review of client/contract/site forms, agreed location hierarchy, archive policies, site permissions and mock-free CRUD acceptance tests. It must not start automatically at the end of Phase 0.
